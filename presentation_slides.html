OUTPUT REQUIREMENT (STRICT) • pred_answer: Đúng 1 ký tự lựa chọn ("A"/"B"/"C"/"D") • raw_output: Báo cáo phân tích chuyên môn & lời giải thích • Constraint: Invalid Response Rate phải giữ ở 0.0%

02. SYSTEM ARCHITECTURE
Kiến Trúc Multi-Agent Đa Chuyên Gia (5 Agents Core)
1. Classifier
Phân loại câu hỏi & phương án chọn vào 5 chuyên khoa sâu (Pathology, Pharmacology...).
2. Analysis
Kích hoạt các Agent chuyên gia tương ứng phân tích ca bệnh độc lập theo góc nhìn từng ngành.
3. MedRAG
Truy xuất chứng cứ y khoa từ Textbooks/PubMed bằng MedCPT vector encoder (Top-32).
4. Synthesis
Tổng hợp các bài phân tích chuyên gia & tri thức RAG thành bản báo cáo hợp nhất.
5. Verifier
Bỏ phiếu & sửa đổi đồng thuận (tối đa 3 rounds) nhằm loại bỏ thông tin mâu thuẫn.

03. DUAL-LAYER MEMORY SYSTEM
Cơ Chế Bộ Nhớ Hai Tầng (Short-Term & Long-Term Memory)
Short-Term Memory (In-RAM State)
  • Scope: Tồn tại trong bộ nhớ RAM trong suốt lượt xử lý của 1 câu hỏi.
  • Vai trò: Lưu giữ trạng thái trung gian giữa các Agent (domain tags, analyses, RAG snippets, vote history).
  • Lifecycle: Tự động reset (`reset_short()`) khi chuyển câu hỏi mới để tránh nhiễm độc ngữ cảnh.
Long-Term Memory (Persistent Cache)
def make_key(question: str, options: Any) -> str: raw = question.strip() + str(options) return hashlib.sha256(raw.encode('utf-8')).hexdigest()[:16]

• Skips redundant LLM inference cho các câu hỏi trùng lặp (from_cache=True).
• Đạt độ trễ 0ms và chi phí 0 token cho các câu hỏi đã lưu trong file JSON disk cache.

05. BENCHMARK & METRICS
Quy Trình & Công Thức Đánh Giá Thống Kê
1. Accuracy & Gain
Accuracy = Correct / N

• N = 1,273 câu MedQA-USMLE test set chính thức.
• Accuracy Gain = Accuracy(V3) - Accuracy(V0).

2. McNemar Test
chi^2 = (|b - c| - 1)^2 / (b + c)

• b: V0 đúng, V3 sai.
• c: V3 đúng, V0 sai.
• Xác nhận sự cải thiện có ý nghĩa thống kê (p < 0.05).

3. Bootstrap CI 95%
CI_95% = [Q_0.025, Q_0.975]

• Lấy mẫu lại Bootstrap B = 1000 iterations.
• Invalid Rate = Invalid Predictions / N (Mục tiêu 0%).

08. ERROR ANALYSIS & INSIGHTS
Phân Tích Lỗi & Hướng Phát Triển Cuối Kỳ
Phân Tích Ca Lỗi Thường Gặp

1. Conflicting Opinions: Khi các Agent bất đồng ý kiến gay gắt trong triệu chứng đan xem phức tạp, Verifier đôi khi rơi vào vòng lặp hòa giải không đạt đồng thuận tuyệt đối.

2. RAG Retrieval Noise: Đoạn văn y khoa truy xuất chứa thuật ngữ trùng lặp nhưng không mang giá trị chẩn đoán phân biệt cho câu hỏi.

Kết Nối Đề Tài Cuối Kỳ (Attack & Defense)

• Hệ thống MedRAGAgents V3 vừa hoàn thành sẽ được làm Target System cho bài toán Tấn công (Prompt Injection, RAG Poisoning) và Phòng thủ y khoa ở Đồ án Cuối kỳ.

• Thử nghiệm thuật toán Tối ưu hóa Tiến hóa (Evolutionary Optimization) cho prompt của Verifier.
